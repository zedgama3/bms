# boundaries: amendment history

Amendment narratives, reasons and folded-in changes moved verbatim out of `plan/design/boundaries.md` on 2026-10-31. The spec body holds the rules; this file holds the record.

## Amendments

- **A1, 2026-10-31 (after step 1's review; approved by the owner 2026-10-31; folded in 2026-10-31).** The seam check's closure rule (Behavior, "The seam table and its check", rules 5–6) is redefined on *where a capture is stored* instead of the enclosing function's result type: a func literal or `assembly` method value stored in a project package's struct literal is a seam (5b; a literal must be extracted and named, a method value is listed as `assembly.<m>`); one returned from a function with an `*assembly` receiver or parameter is a seam keyed by that function (5a, as before, now also when the function holds a method value `a.<m>` rather than a literal); one in an app-declared struct, a local, a goroutine or a call argument is wiring (6). The committed test's kinds (`type`, `closure`), receiver keys (`assembly.<m>`), any-use capture, "no longer late-bound" rows and the three document errors are recorded as the rule. Reason: a seam is a value a package keeps, and its signature is whatever the package asked for. Effect today: one row, `assembly.auditActor`, joins the table at the step-1 follow-up and leaves in step 3; no literal needs extracting. Risks gains the test's two blind spots. Folded in on re-approval (`spec-editor`): the Summary's "18 rows" becomes "18 rows, 19 after A1"; Failure modes gain B31 (a stored literal: extract and list, `TestSeamTable_FlagsStoredLiteral`) and B32 (a stored method value not in the table, `TestSeamTable_FlagsStoredMethodValue`); Proposed change 9 (`go-conventions`) gains "A core package takes a seam as an `Options` or `Decl` field, never as a method argument it retains."
