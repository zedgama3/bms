# config: process configuration

- **Status:** Approved (2026-10-16)
- **Package:** `internal/config` (Go module `github.com/zedgama3/bms`; foundation-level, not
  a bms module). **UI:** none.
- **Depends on specs:** `lib-errs.md` (Implemented): `errs.E`, `errs.Is`, kinds `Invalid`,
  `Internal`, `Canceled`, `Timeout`. `lib-core.md` (Implemented): `validate.Errors`,
  `validate.FieldError`, `validate.Fields`, `validate.NonEmpty`, `validate.Range`,
  `validate.OneOf`, `validate.URL`, `validate.ListenAddr`. `lib-secret.md` (Implemented):
  `secret.Secret`, `secret.New`, `Value`, `IsSet`. `module-contract.md` (Approved): decision
  7 and Proposed change 10 (`modules.disabled`, opt-out enablement; `Env.Enabled`).
  **Used by:** `cmd/bms` (calls `Load` once, prints problems) and `app` (hands each section
  to the core package it is for, derives `module.Env.Enabled`). Nothing else imports
  `config` (layer rules 2 and 3 in `07-abstractions.md`): the core and the modules receive
  typed options from `app`.

## Summary

**Purpose.** Turn what the operator sets in the environment into one typed, validated `Config` the process starts from. Package `internal/config`; imports stdlib, `lib/errs`, `lib/validate`, `lib/secret` (depguard rule `config`); only `cmd/bms` and `app` may import it. Not runtime settings (`settings`), not `OTEL_*` (`telemetry`), not read-only detection (`db`). No tables, permissions, signals, routes or UI.

**Exported names.**
- `Prefix = "BMS_"`, `TestPrefix = "BMS_TEST_"` (never read by `Load`), `MaxSecretFileBytes = 64<<10`, `SecretsFileName = "secrets.json"`, `SecretsFieldSessionKey = "session_key"`.
- `Key{Name, Env, Default, Required, Secret, Generated, Doc}` and `Keys() []Key` (copy of the single source of truth; `Env` = `BMS_` + upper-cased Name with `.` replaced by `_`).
- `Config{Instance, DB, HTTP, Session, Secrets, Log, Data, Modules}`: immutable value, safe to log or marshal (credentials are `secret.Secret`). Sections: `Instance{Name}`, `DB{URL secret.Secret, MaxConns, ConnectTimeout, QueryTimeout}`, `HTTP{Addr, RequestTimeout, ShutdownTimeout, MaxBodyBytes int64, TrustedProxies []netip.Prefix, AllowPlaintext}`, `Session{Key secret.Secret}`, `Secrets{File}`, `Log{Level slog.Level, Format LogFormat}` (`LogJSON`, `LogText`), `Data{Dir}`, `Modules{Disabled []string}`.
- `Default() Config` (defaults applied, `db.url` unset, so `Validate` fails on `BMS_DB_URL` only); `Load(ctx, environ []string) (Config, error)`; `(Config) Validate() error` (no I/O).

**Catalogue (variable: default, range).** `BMS_INSTANCE_NAME` main, 1..64 `[a-z0-9]([a-z0-9-]*[a-z0-9])?`; `BMS_DB_URL` (+`_FILE`) required secret, `postgres`/`postgresql` URL with host, <= 4096 bytes, no NUL; `BMS_DB_MAX_CONNS` 10, 1..1000; `BMS_DB_CONNECT_TIMEOUT` 30s, 1s..10m; `BMS_DB_QUERY_TIMEOUT` 10s, 100ms..10m; `BMS_HTTP_ADDR` 127.0.0.1:8080 (non-loopback needs trusted proxies or allow_plaintext); `BMS_HTTP_REQUEST_TIMEOUT` 30s, 1s..10m; `BMS_HTTP_SHUTDOWN_TIMEOUT` 15s, 1s..5m; `BMS_HTTP_MAX_BODY_BYTES` 1048576, 1024..1073741824; `BMS_HTTP_TRUSTED_PROXIES` empty, <= 64 prefixes or bare addresses, no zero-bit prefix; `BMS_HTTP_ALLOW_PLAINTEXT` false; `BMS_SESSION_KEY` (+`_FILE`, else secrets file) generated, when set 32..1024 bytes, no NUL; `BMS_SECRETS_FILE` `<data.dir>/secrets.json`; `BMS_LOG_LEVEL` info (debug|info|warn|error); `BMS_LOG_FORMAT` json (json|text); `BMS_DATA_DIR` data; `BMS_MODULES_DISABLED` empty list, <= 64 unique non-empty items.

**Key decisions.**
1. Environment is the only source (no file, no `.env`). 2. No command-line flags for values.
3. One `Config` fully validated for every command; an unset generated secret is the command's check.
4. `FieldError.Field` is the environment variable name, not the dotted key.
5. Secrets are `secret.Secret` and accept `*_FILE`; both forms set is an error.
6. No read-only flag; `db` detects it.
7. Session key generated by `bms migrate` into `secrets.json` (0600, dir 0700, never overwritten, 64 bytes base64, atomic add of new fields), read by `config` as a third source; two sources is an error; operator told to back it up separately.
8. Unknown `BMS_*` variables fail (case-insensitive prefix; `BMS_TEST_*` exempt).
9. Empty value means unset; non-secrets trimmed, env secrets verbatim, `_FILE` loses trailing CR/LF only.
10. Strict grammars (no `10.0`, no unitless duration, enums exact).
11. `modules.disabled` shape checked here, registration checked in `app`.
12. Sections are config's own types; `app` copies them into each package's options.
13. `Load` takes `[]string`. 14. Byte count is a plain integer.
15. `log.format` offers `text` as well as JSON (owner, 2026-10-16).
16. TLS is offloaded to a front end under stated conditions; bind rule F28 (non-loopback bind needs `trusted_proxies` or `allow_plaintext`), F30 (no zero-bit trusted prefix); loopback recognised by literal host, no DNS.

**What callers handle.** `Load` returns the zero `Config` and one `errs.Invalid` joining every problem (catalogue order, unknown variables last), each a `validate.FieldError` named by env variable, never echoing a value (read with `validate.Fields`). Other kinds: `Internal` for an `environ` entry without `=` (F12); `Canceled`/`Timeout` if ctx ends during file reads (F13). A missing secrets file is not an error: `Session.Key` stays unset. Failure modes F1-F30; obligations on `app`: F22 (unknown disabled module, `Invalid` under `BMS_MODULES_DISABLED`, derive `module.Env.Enabled`) and F22b (commands that sign sessions refuse an unset key, naming the secrets file). Secrets-file problems (F23-F27) are `Invalid` under `BMS_SECRETS_FILE`/`BMS_SESSION_KEY`: not a regular file, group/other bits set (Unix), malformed JSON, bad key length, key in both env and file.

**Config vs settings rule.** Configuration is what reaches the database or listens, credentials and security boundaries, per-process values, and what fixes what may run before `migrate`. Everything else is a runtime setting (`settings`). Reloading is not supported.

**Expects of dependencies.** `lib-errs`: `E`, `Is`, kinds `Invalid`, `Internal`, `Canceled`, `Timeout`. `lib-core`: `validate.Errors`, `FieldError`, `Fields`, `NonEmpty`, `Range`, `OneOf`, `URL`, `ListenAddr` (holds no `retry.Policy`). `lib-secret`: `Secret`, `New`, `Value`, `IsSet`; a Secret decoded from the secrets file refuses the marker texts. `module-contract` decision 7 / Proposed change 10: opt-out enablement via `modules.disabled`, `Env.Enabled`. Expected of `app`: `Load` once per process, print `<Env>: <Reason>` per field (exit 2), `bms migrate` generates the secrets file via `app/secrets.Ensure`, copies sections into `db`, `api`, `identity`, `telemetry`, `audit` options.

## Purpose

Turn what the operator sets in the environment into one typed, validated value the process
starts from.

## Responsibilities

- Define the **catalogue of keys**: every configuration value the process accepts, with its
  dotted name (`db.url`), its environment variable (`BMS_DB_URL`), its type, its default and
  whether it is required or secret. One table drives loading, validation, `bms check` and
  the operator documentation.
- **Load** the values from the environment (`os.Environ()` form), including a secret's
  `*_FILE` variant, and apply defaults.
- **Read the generated-secrets file** (`secrets.json` under `data.dir` by default, written
  once by `bms migrate`; decision 7): its format, its permission check, and how it combines
  with the environment. `config` reads it; it never writes it.
- **Parse** each value by its type with one strict grammar per type (integer, duration,
  byte count, enum, list, CIDR list, listen address, URL).
- **Validate** the whole value and report every problem at once, each naming the
  environment variable to fix, never echoing a value (09 §1: "Configuration errors are all
  reported at once, with the setting's name").
- Hold every credential in `secret.Secret`, so the loaded value can be logged or marshalled
  without leaking (lib-secret Proposed change 1).
- Refuse unknown `BMS_*` variables, so a typo in a name is an error and not a silent default.

See "Settings" below for the rule that draws the line. |

| Generating the session key, writing the secrets file, telling the operator to back it up | `app` (`app.md`), in `bms migrate` (decision 7, Proposed change 3). `config` only reads the file. |

## Sub-abstractions

| Name | Purpose (one line) | Notes |
|---|---|---|
| `Key`, `Keys` | Name every value the process accepts, once, with its variable, default and kind. | The table `Load` walks; exported for `bms check` and the docs test. |
| `Load` | Read the environment into a `Config`, reporting every problem at once. | `os.Environ()` in; `_FILE` for secrets; unknown `BMS_*` refused. |
| Secrets file | Read the secrets `bms migrate` generated, from one file with a fixed shape and owner-only permissions. | `secrets.json`; JSON object; today one field, `session_key`. Read-only here. |
| Grammars | Parse one text form per type, strictly. | Boolean, integer, duration, byte count, enum, list, CIDR list, listen address, URL. Unexported; pinned by tests. |
| `Config` and sections | Carry the typed values to `app`, immutably. | `Instance`, `DB`, `HTTP`, `Session`, `Log`, `Data`, `Modules`. |
| `Validate` | Check ranges and shapes, naming the variable and never the value. | Runs inside `Load`; callable on a hand-built `Config` in tests and `app`. |

## Interface

```go
// Package config loads the process configuration from the environment and validates it,
// reporting every problem at once. It depends on the standard library and internal/lib
// only. cmd/bms and app are its only importers; the core and the modules receive typed
// options from app.
package config

import (
	"context"
	"log/slog"
	"net/netip"
	"time"

	"github.com/zedgama3/bms/internal/lib/secret"
)

// Prefix is the start of every environment variable this package reads. Any variable
// whose name starts with it (ignoring case) must be a known key, or Load fails (F11);
// variables starting with TestPrefix are left alone.
const (
	Prefix     = "BMS_"
	TestPrefix = "BMS_TEST_" // read by integration tests, never by Load
)

// MaxSecretFileBytes caps a *_FILE read and the secrets file. A larger file fails Load (F9).
const MaxSecretFileBytes = 64 << 10

// The generated-secrets file (decision 7). bms migrate creates it under Data.Dir with
// crypto/rand material, mode 0600, and never overwrites it; Load reads it. It is a JSON
// object; unknown fields are preserved by migrate and ignored by Load, so a rollback to an
// older binary still starts. Today it holds one field.
const (
	SecretsFileName        = "secrets.json" // default: filepath.Join(Data.Dir, SecretsFileName)
	SecretsFieldSessionKey = "session_key"  // string; the material Session.Key holds
)

// Key describes one configuration value. Keys() is the single source of truth: Load
// reads exactly these variables, Validate reports problems under Env, bms check and the
// operator documentation list them. Env is derived from Name: Prefix plus Name upper-cased
// with "." replaced by "_" (db.max_conns -> BMS_DB_MAX_CONNS).
type Key struct {
	Name      string // dotted: "db.url"
	Env       string // "BMS_DB_URL"
	Default   string // text form of the default; "" when Required or Generated
	Required  bool   // Load fails when neither Env nor Env+"_FILE" is set (F1)
	Secret    bool   // held in secret.Secret; Env+"_FILE" accepted; never echoed
	Generated bool   // also read from the secrets file; bms migrate creates it when absent
	Doc       string // one English line for operators, e.g. "PostgreSQL connection URL"
}

// Keys returns the catalogue in the order of the sections below, as a copy. Cannot fail.
// Consumers: Load (internally), cmd/bms (`bms check` and usage text), the docs test.
func Keys() []Key

// Config is the whole process configuration. It is a value: immutable once Load returns,
// safe to copy, share, marshal and log (every credential is a secret.Secret). The zero
// value is not usable; start from Default() or Load.
type Config struct {
	Instance Instance
	DB       DB
	HTTP     HTTP
	Session  Session
	Secrets  Secrets
	Log      Log
	Data     Data
	Modules  Modules
}

// Instance identifies this process among the copies of one installation (D27: on-site and
// off-site copies share a database but are different processes).
type Instance struct {
	// Name is recorded by audit as "which copy" (09 §8) and by telemetry as a resource
	// attribute. Grammar: "[a-z0-9]([a-z0-9-]{0,62}[a-z0-9])?" (1..64). Default "main".
	Name string
}

// DB is what db needs to open the pool. app copies it into db's own options type.
type DB struct {
	// URL is the PostgreSQL connection URL: postgres:// or postgresql:// with a host. It is
	// a secret because it carries the password. Required. BMS_DB_URL or BMS_DB_URL_FILE.
	URL secret.Secret
	// MaxConns is the pool's upper bound. Default 10; 1..1000.
	MaxConns int
	// ConnectTimeout bounds the initial connect at start-up, retries included. Default 30s;
	// 1s..10m.
	ConnectTimeout time.Duration
	// QueryTimeout is the deadline a caller derives for one statement when it has no
	// tighter one. Default 10s; 100ms..10m.
	QueryTimeout time.Duration
}

// HTTP is what the api shell needs to listen. TLS is offloaded to a front end; decision
// 16 states the conditions and the rule Validate enforces on Addr, TrustedProxies and
// AllowPlaintext (F28).
type HTTP struct {
	// Addr is the listen address, "host:port" or ":port". Default "127.0.0.1:8080"
	// (loopback: safe without a front end). Binding anything else needs TrustedProxies or
	// AllowPlaintext (F28).
	Addr string
	// RequestTimeout is the deadline of one request. Default 30s; 1s..10m.
	RequestTimeout time.Duration
	// ShutdownTimeout is how long in-flight requests get to finish at stop (09 §1).
	// Default 15s; 1s..5m.
	ShutdownTimeout time.Duration
	// MaxBodyBytes caps a request body (JSON API; file uploads are files' later concern).
	// Default 1048576 (1 MiB); 1024..1073741824.
	MaxBodyBytes int64
	// TrustedProxies lists the networks whose X-Forwarded-For and X-Forwarded-Proto are
	// believed (D15: an optional front end). Empty, the default, trusts none. At most 64
	// prefixes; a bare address means that one address. Non-empty, it is also what makes a
	// non-loopback Addr acceptable: the plaintext hop ends at these proxies. A prefix of
	// zero bits (0.0.0.0/0, ::/0) is refused (F30): it would trust every peer's headers
	// and switch off the api's peer check. A front end on the same host is listed as
	// 127.0.0.1/32 (or ::1/128); otherwise all its clients share the loopback address.
	TrustedProxies []netip.Prefix
	// AllowPlaintext permits a non-loopback Addr with no TrustedProxies: plain HTTP
	// reachable from the network, for development only. Default false. The api shell logs
	// a warning at start when it is true.
	AllowPlaintext bool
}

// Session is what identity needs to sign session tokens without a database write (09 §2).
type Session struct {
	// Key is the signing key material; identity derives purpose-specific keys from it.
	// Sources, in this order: BMS_SESSION_KEY, BMS_SESSION_KEY_FILE, the secrets file's
	// "session_key" (decision 7); more than one source set is an error (F7, F27). Unset
	// when no source has it (the secrets file is missing or lacks the field): Validate
	// accepts that, and the command that needs the key refuses to run (F22b in app). When
	// set: 32..1024 bytes, no NUL. The same value on every copy of one installation.
	Key secret.Secret
}

// Secrets says where the generated-secrets file is.
type Secrets struct {
	// File is the path of the secrets file. Default filepath.Join(Data.Dir, SecretsFileName),
	// resolved at Load after data.dir. BMS_SECRETS_FILE. The file may be absent (then
	// Session.Key is unset); when present it must be a regular file readable by its owner
	// only (mode 0600 on Unix; F24).
	File string
}

// LogFormat is how telemetry writes log lines to stdout.
type LogFormat string

const (
	LogJSON LogFormat = "json" // default; D20
	LogText LogFormat = "text" // for a developer's terminal
)

// Log is what telemetry needs to build the logger.
type Log struct {
	// Level is the minimum level written: "debug", "info", "warn" or "error". Default info.
	Level slog.Level
	// Format is "json" or "text". Default json.
	Format LogFormat
}

// Data is where this process keeps local files: the secrets file (decision 7), the audit
// spool on a read-only copy (09 §8), later files' local-disk storage.
type Data struct {
	// Dir is a directory path, absolute or relative to the working directory. Default
	// "data". bms migrate creates it (mode 0700); other consumers check it at Start. Load
	// only uses it to resolve Secrets.File.
	Dir string
}

// Modules is the opt-out list of module-contract decision 7.
type Modules struct {
	// Disabled names compiled-in modules not to run. Default empty: every compiled-in
	// module runs. Items are unique and non-empty; app checks each is registered.
	Disabled []string
}

// Default returns a Config with every default applied, every required value unset and
// Session.Key unset. Default().Validate() therefore fails on the required key (db.url)
// only; tests set it. Cannot fail. Consumers: Load (its starting point), tests in app and
// config.
func Default() Config

// Load reads environ (entries "NAME=value", as os.Environ returns them), applies defaults,
// parses every known key, reads *_FILE variants for secrets and the secrets file if it
// exists, validates, and returns the Config or one error that joins every problem found
// (F1–F29). Each problem is a validate.FieldError whose Field is the environment variable
// to fix (BMS_SECRETS_FILE for the secrets file) and whose Reason never contains a value.
// A missing secrets file is not a problem here: Session.Key is left unset for the command
// to judge. ctx bounds the file reads. Safe for concurrent use.
// Consumers: cmd/bms (once per process); app's tests with a hand-made environ.
func Load(ctx context.Context, environ []string) (Config, error)

// Validate checks every section's ranges and shapes (F14–F21, F28) and fails with
// errs.Invalid joining one validate.FieldError per problem, Field being the variable's Env
// name. An unset Session.Key passes (decision 7). It does no I/O: it does not open
// Data.Dir or Secrets.File, resolve HTTP.Addr or connect to DB.URL.
// Consumers: Load; app's tests building a Config by hand.
func (c Config) Validate() error
```

## Types

Defines `Key`, `Config`, `Instance`, `DB`, `HTTP`, `Session`, `Secrets`, `LogFormat`, `Log`,
`Data`, `Modules`. Uses `secret.Secret` (lib-secret), `netip.Prefix`, `slog.Level`, `time.Duration`,
`validate.FieldError` and `validate.Errors` (lib-core). Uses nothing from `model` (no key
holds an ID, a sensitivity or an address) and nothing from `core/`.

| `http.trusted_proxies` | `BMS_HTTP_TRUSTED_PROXIES` | CIDR list | empty | each a prefix or an address; ≤ 64; no prefix of zero bits (F30); a front end on the same host is listed as `127.0.0.1/32`, otherwise all its clients share the loopback address | api, identity (rate limit by address) |
| `http.allow_plaintext` | `BMS_HTTP_ALLOW_PLAINTEXT` | bool | `false` | `true` or `false` | config (F28), api (start-up warning) |
| `session.key` | `BMS_SESSION_KEY` (+`_FILE`), else the secrets file | secret, generated | none: `bms migrate` generates it | when set: 32..1024 bytes, no NUL; one source only (F7, F27); unset refused by the commands that need it (F22b, app) | identity |
| `secrets.file` | `BMS_SECRETS_FILE` | path | `<data.dir>/secrets.json` | non-empty; if the file exists: regular, owner-only permissions, ≤ 64 KiB, a JSON object (F23–F25) | config, app |
| `log.level` | `BMS_LOG_LEVEL` | enum | `info` | `debug`, `info`, `warn`, `error` | telemetry |
| `log.format` | `BMS_LOG_FORMAT` | enum | `json` | `json`, `text` | telemetry |
| `data.dir` | `BMS_DATA_DIR` | path | `data` | non-empty after trimming; no NUL | audit, files |
| `modules.disabled` | `BMS_MODULES_DISABLED` | list | empty | items non-empty after trimming, unique; ≤ 64; registered (checked by app) | app |

Variables the process reads that are **not** in the catalogue and are not `BMS_*`:
`OTEL_*` (`telemetry.md`, D20) and, if `db` chooses to honour them, pgx's `PG*`.
`BMS_TEST_*` are read only by integration tests. `telemetry` validates the `OTEL_*`
variables it reads itself (its table "What is read from the environment":
`OTEL_SDK_DISABLED`, the `OTEL_EXPORTER_OTLP_*ENDPOINT` and `*PROTOCOL` variables,
`OTEL_TRACES_SAMPLER`, `OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES`) at start, and a
bad value fails `telemetry.New` with `errs.Invalid` naming the variable, printed by
`cmd/bms` like a config failure; `OTEL_EXPORTER_OTLP_PROTOCOL`, when set, must be
`http/protobuf` (`grpc` is refused: telemetry.md decision 5). The rest of `OTEL_*` is read
by the OpenTelemetry SDK with its own defaults. `config` still neither reads nor validates
any of them.

## Data

No tables. `config` reads two kinds of file and writes none: the files that `*_FILE`
variables name, and the generated-secrets file, whose format this spec fixes and whose
writer is `bms migrate` (`app.md`, Proposed change 3):

| File | Path | Owner | Mode | Content |
|---|---|---|---|---|
| secrets file | `secrets.file` (default `<data.dir>/secrets.json`) | created by `bms migrate`, read by `config` | regular file, 0600; directory 0700 | a JSON object: `{"session_key": "<64 random bytes from crypto/rand, standard base64>"}`; later generated secrets are further fields; unknown fields preserved |

Nothing here is personal data. `DB.URL` and `Session.Key` are credentials: held in
`secret.Secret` from the moment they are read, never echoed in a `FieldError.Reason`, never
logged (a test pins that `slog.Any` and `encoding/json` on a `Config` show the markers
only). The secrets file is the one credential at rest that bms itself creates; it is kept
out of the database so that a database dump does not carry it (decision 7), and the
operator is told at creation to back it up separately.

## Permissions

None. `Load` runs at process start with no actor; nothing here is reachable through HTTP.
`bms check` is run by the operator on the host; the operating system's permissions on the
environment and the `*_FILE` files are the access control.

## Signals

None published, none subscribed.

## Settings

None of its own. This spec draws the line between process configuration and runtime
settings, which later specs follow:

**A value is configuration (here) when any of these holds:** it is needed to reach the
database or to start listening (`db.*`, `http.addr`); it is a credential or a security
boundary that a web admin must not be able to change (`db.url`, `session.key`,
`secrets.file`, `http.trusted_proxies`, `http.allow_plaintext`); it differs per process
rather than per regional (`instance.name`, `data.dir`, `log.*`, the on-site copy versus the
off-site one, D27); or it fixes what the
process may touch before `bms migrate` runs (`modules.disabled`, module-contract decision
7). **Everything else is a setting** (`settings.md`): typed, defaulted, edited by a settings
admin, audited, effective without a restart. Examples, each settled elsewhere: default
language (D28), retention per module and level (D30), terminology, branding, the public URL
(09 §9; also the installation's identity, D18, shared by every copy and therefore not a
process value), SMTP (09 §6), sign-up mode (D21), required profile fields (09 §3), what a
person sees of views of their data (D22), session lifetime and login rate limits
(`identity.md`; regional policy, so settings with defaults).

Regional differences never appear here as code paths: every row of the catalogue has a
default a regional can leave alone, and nothing in it names a regional, a department or a
vendor.

## UI

None. `bms check` (a command, `app.md`) prints the result of `Load`: on failure, one line
per `validate.FieldError` as `<Env>: <Reason>`; on success, every key with its effective
value, secrets shown as `[redacted]` or `[unset]`, an unset `Generated` key marked "run
`bms migrate`", and the path of the secrets file. `bms migrate` prints decision 7's back-up
notice when it creates that file.

## Behavior

### Decisions settled here, with reasons

1. **The environment is the only source: no configuration file, no flags, no `.env`
   parsing.** Every deployment tool an operator will use (systemd `EnvironmentFile=`,
   compose `env_file`, container platforms, a shell) already turns a file into an
   environment, and one source means one precedence rule and nothing to document about
   which wins. A TOML or YAML parser would be the first third-party dependency in the
   foundation for no gain. Development runs `set -a; . deploy/compose/.env` or exports the
   variables; the Makefile may do that for `make run` later.
2. **No command-line flags for configuration values.** Commands (`serve`, `migrate`,
   `check`, ...) and their arguments (a person ID for `export`) are `cmd/bms`'s; a value
   that can come from two places is a value that is set in the wrong one. Settled with
   decision 1.
3. **One `Config` for every command, fully validated every time; a generated secret's
   presence is the command's check.** Everything the operator sets is validated regardless
   of command, so `bms check` finds every problem and an operator never discovers a bad
   value by the next command they run. The session key is not something the operator sets
   (decision 7): `Load` leaves it unset when no source has it, `Validate` accepts that, and
   `app` decides per command: `migrate` generates it, every other command that signs or
   verifies a session refuses to run and says what to do (F22b). The one required variable
   before the first migration is `BMS_DB_URL`.
4. **`FieldError.Field` is the environment variable name, not the dotted key.** The
   operator fixes a variable; `validate.Fields(err)` printed one per line is then directly
   actionable (`BMS_DB_MAX_CONNS: must be between 1 and 1000, got 0`). The dotted name is
   the key's identity in the plan and in `Key.Name`; `Key.Env` is derived from it
   mechanically, so neither can drift.
5. **Secrets are `secret.Secret` from the moment they are read and support `*_FILE`.**
   Container platforms mount secrets as files; an environment variable is visible to every
   process the same user runs. Both `BMS_X` and `BMS_X_FILE` set is an error, not a
   precedence: silently preferring one hides a stale value. The same rule covers the
   secrets file: a key present both in the environment (either form) and in the secrets
   file is an error (F27). Only secret keys accept `_FILE`; there is no reason to read a
   port from a file, and fewer rules are fewer tests.
6. **No read-only flag; `db` detects it.** A flag can lie in both directions: "read-only"
   on a primary merely blocks writes, "writable" on a replica changes nothing because the
   database refuses the writes anyway. `pg_is_in_recovery()` is the truth, `db` already
   owns the check (module-contract Proposed change 4), and `/readyz` reports what `db`
   found. If the switchover design (Q-OFFLINE) later needs "refuse writes before the
   database is demoted", that is a new key (`db.read_only`, default `false`) added then,
   with the mechanism unchanged.
7. **The session key is generated at installation into a secrets file outside the
   database, and the operator is told to back it up.** Confirmed by the owner (2026-10-16):
   generated during the initial installation, stored in a configuration file (as GitLab's
   `gitlab-secrets.json` is), with a notice at install time that it must be backed up.
   The design:
   - **Who and when:** `bms migrate` (the install step every operator already runs first,
     D17), before touching the database. If no source provides `session.key` (no
     `BMS_SESSION_KEY`, no `_FILE`, no `session_key` in the secrets file), it creates
     `data.dir` (0700) if needed and writes `secrets.file` with `O_CREATE|O_EXCL`, mode
     0600, holding 64 bytes from `crypto/rand` in standard base64. If the file exists but
     lacks a field this version generates, it adds the field, rewriting atomically
     (temporary file in the same directory, `fsync`, rename) and preserving every other
     field. It never overwrites an existing value. Generation lives in `app` (a small
     helper, `app/secrets`), because `config` is a loader and `app` owns the commands
     (Proposed change 3).
   - **The notice**, printed by `migrate` on stderr whenever it created the file or added a
     field, framed so it stands out from the migration log: "Created `<path>`. It holds
     this installation's session key. Back it up separately from the database and copy it
     to every copy of this installation; without it, every session is invalid and anything
     sealed with it is unreadable. Keep it readable by the bms user only." `bms check`
     prints the path of the secrets file in its summary so an operator can confirm what to
     back up at any time.
   - **How `config` reads it:** as a third source for `session.key`, after the environment
     and `_FILE` (Behavior: "`Load`, step by step", step 5). A key provided by the
     environment wins nothing: two sources is an error (F27), so container platforms that
     inject `BMS_SESSION_KEY` simply never get a secrets file, because `migrate` sees the
     key is set and generates nothing.
   - **Why outside the database:** sessions are verified without a database write (09 §2),
     every copy of one installation must hold the same key, and privacy-data warns that
     backups contain everything: a key kept in the database travels with every dump, and a
     leaked dump would then mint sessions for any admin until someone rotates it. A file
     the operator backs up separately does not.
   - **Future generated secrets** (a sealing key if `settings` stores the SMTP password)
     are further fields of the same file, generated the same way by `migrate`, declared in
     the catalogue as `Generated` keys and read by `Load`. One file to back up, one notice.
   - **Rotation** is a later command (`bms rotate-secret session_key`), designed with
     `identity.md`; it is not needed for the MVP and the file format allows it (a new
     value, old sessions invalid).
8. **Unknown `BMS_*` variables fail loading.** `BMS_DB_MAXCONNS=5` would otherwise leave
   the default in place without a word. The check ignores case on the prefix so
   `bms_db_url` is caught too, and exempts `BMS_TEST_*`, which the integration tests own
   (`deploy/compose/.env.example`).
9. **An empty value means unset.** `BMS_MODULES_DISABLED=` is "disable nothing" and
   `BMS_SESSION_KEY=` is "not set" (required, so an error), which is what compose and
   systemd produce for an empty assignment. Non-secret values are trimmed of surrounding
   whitespace; secrets from the environment are taken verbatim; a `*_FILE` has its trailing
   CR and LF bytes removed (editors and `docker secret` add one) and nothing else.
10. **Grammars are strict.** `BMS_DB_MAX_CONNS=10.0`, `BMS_HTTP_REQUEST_TIMEOUT=30`
    (no unit), `BMS_LOG_LEVEL=Info` and `BMS_MODULES_DISABLED=a,,b` are errors, each with a
    reason that states the rule. Leniency would mean documenting which lenient forms work,
    and the error message is the documentation.
11. **`modules.disabled` is validated for shape here and for existence in `app`.** Checking
    that a name is registered needs `core/module`, which `config` may not import (layer
    rule). Duplicating the module-name grammar here would be a second copy of a rule;
    "registered" implies "well-formed", so `config` checks only non-empty and unique, and
    `app` reports an unknown name as `errs.Invalid` under `BMS_MODULES_DISABLED`, listing
    the compiled-in names, before `Resolve` (see "`modules.disabled`" below).
12. **Sections are `config`'s own types; `app` copies them into each core package's
    options.** Layer rule 2 forbids `db` or `api` importing `config`, so `db.Options` and
    `config.DB` are two structs with the same fields and a few lines in `app` between them.
    That keeps `config` a leaf and lets `db` be built in a test with no environment at all.
13. **`Load` takes `[]string`, not a lookup function.** `os.Environ()` is the natural input,
    it lets `Load` enumerate for the unknown-variable check (decision 8), and a test writes
    `[]string{"BMS_DB_URL=postgres://..."}` with nothing to fake.
14. **The byte count is a plain integer.** `1048576` rather than `1MiB`: a unit grammar
    (`k`/`M`/`Mi`, case rules) is more code and more ways to be wrong than one documented
    default. Revisit if a second byte-count key appears.
15. **`log.format` offers `text` as well as D20's JSON.** Confirmed by the owner
    (2026-10-16): JSON by default, text for developers. D20's "JSON on stdout, always" is
    about what a deployment emits; the default is JSON and nothing in a deployment needs to
    change it. `text` exists for a developer reading a terminal and never appears in the
    deploy examples (Proposed change 12 records the clarification against D20).
16. **TLS is offloaded to a front end, under stated conditions, and the binary enforces
    the part it can.** Confirmed by the owner (2026-10-16): offloading is acceptable as
    long as it does not affect security. Offloading is safe when all of these hold:
    (a) the plaintext hop between the front end and bms is loopback, a private network the
    operator controls, or a tunnel; (b) bms believes `X-Forwarded-For` and
    `X-Forwarded-Proto` only from the front end; (c) the front end sets those headers and
    strips any it received; (d) session cookies are `Secure` and `HttpOnly` whatever the
    hop, and HSTS is sent when the public scheme is https; (e) the front end does not
    terminate authentication (D15: bms does). What this spec enforces: `http.addr` defaults
    to loopback; a non-loopback bind (an explicit interface, or `:port` meaning all) is
    refused unless `http.trusted_proxies` names the front end or `http.allow_plaintext` is
    set for development (F28); forwarded headers are tied to `http.trusted_proxies` (api);
    no trusted prefix of zero bits (F30). What `api.md` enforces (its decisions 7, 8, 9,
    24 and 26, 2026-10-17): (b); (d) with one exception, a development cookie
    `bms_session_dev` without `Secure` only when `allow_plaintext` is on and the request
    is plain `http`; HSTS as `max-age=31536000` without `includeSubDomains`; a warning
    log when `allow_plaintext` is on; and a direct request from a peer outside
    `trusted_proxies` answered `403` with code `misdirected` (not `421`), `/healthz` and
    `/readyz` exempt (Proposed change 5, applied).
    What the deploy docs state: (a), (c), (e), with examples (Proposed change 11). A
    loopback bind is recognised by literal host: empty host is all interfaces (not
    loopback); `127.0.0.0/8`, `::1` and the literal `localhost` are loopback; no DNS lookup
    is made, so `Validate` stays free of I/O.

### `Load`, step by step

1. If `ctx` is done, fail (F13).
2. Split each entry of `environ` at its first `=`; an entry without `=` is a caller bug
   (F12). Later entries for the same name win, as the operating system would resolve them.
3. For every name whose upper-cased form starts with `Prefix` and not `TestPrefix`: if it is
   not the `Env` of a key, or `Env+"_FILE"` of a secret key, record it (F11).
4. Start from `Default()`. For each key in `Keys()`:
   - Non-secret: take the value, trim it; empty means unset and the default stays.
   - Secret: if both `Env` and `Env+"_FILE"` are non-empty, record F7 and skip the key. If
     `Env+"_FILE"` is set: check `ctx` (F13), open the file, read at most
     `MaxSecretFileBytes+1` bytes through `io.LimitReader`, fail if the file could not be
     opened or read (F8) or exceeded the cap (F9), close it (its `Close` error is joined),
     trim trailing `\r` and `\n`. If `Env` is set, take it verbatim. Empty means unset.
   - Parse the text by the key's type (F2–F6, F15, F29); a parse failure records the
     problem and leaves the default in place, and marks the key as failed.
5. Resolve `Secrets.File` (the variable, else `filepath.Join(Data.Dir, SecretsFileName)`)
   and read the secrets file: check `ctx` (F13); `os.Stat` it; if it does not exist, every
   `Generated` key not set by the environment stays unset and this step ends. Otherwise it
   must be a regular file (F23) whose mode has no group or other bits (`mode & 0o077 == 0`;
   F24; skipped on Windows, where the check is documented as the operator's); open and
   read it through `io.LimitReader` at `MaxSecretFileBytes+1` (F23, F9); decode it as a
   JSON object with `encoding/json` into a struct of `secret.Secret` fields matching the
   known field names, unknown fields ignored (F25). For each `Generated` key with a
   non-empty value in the file: if the environment (either form) also set it, record F27
   under the key's `Env` and mark it failed; else take the file's value.
6. Call `Validate()` on the result; drop any `FieldError` whose `Field` is a key marked
   failed in steps 4 and 5 (one problem per key, F19), keep the rest, including "required"
   for `db.url` when unset (F1). An unset `Session.Key` produces no problem.
7. If anything was recorded, return the zero `Config` and one error:
   `validate.Errors{Op: "config.Load"}` holding every problem, in catalogue order, so
   `errs.Is(err, errs.Invalid)` holds and `validate.Fields(err)` lists each. Otherwise return
   the `Config` and nil.

Steps 4 and 5 hold the package's only I/O: reading regular files the operator named (or
the default secrets path), bounded by the cap and by `ctx`. `Load` never writes, never
follows a path into a directory listing or a network. No log output: `config` has no
logger; `cmd/bms` prints what `Load` returns.

### `Validate`, per section

| Section | Rules (each a `FieldError` under the variable) |
|---|---|
| `Instance` | `Name` matches the grammar (F17). |
| `DB` | `URL` set (F1); `validate.URL(env, url, "postgres", "postgresql")` (F15); ≤ 4096 bytes and no NUL (F15). `MaxConns`, `ConnectTimeout`, `QueryTimeout` in range (F14). |
| `HTTP` | `validate.ListenAddr` on `Addr` (F18); the three durations and `MaxBodyBytes` in range (F14); `len(TrustedProxies) <= 64` (F20); each prefix valid (`Prefix.IsValid()`, F6 when built by hand) and of at least one bit (`Prefix.Bits() > 0`, F30, under `BMS_HTTP_TRUSTED_PROXIES`, reason "trusts every peer: list the front end's addresses or networks"); `Addr`'s host not loopback and `TrustedProxies` empty and `!AllowPlaintext` → F28 under `BMS_HTTP_ADDR`, reason "binds a non-loopback address with no trusted proxy: put a TLS front end in front and list it in BMS_HTTP_TRUSTED_PROXIES, bind 127.0.0.1, or set BMS_HTTP_ALLOW_PLAINTEXT=true for development". |
| `Session` | if `Key` is set: 32..1024 bytes and no NUL (F16). Unset passes (decision 7). |
| `Secrets` | `File` non-empty after trimming and no NUL (F21, same rule as `data.dir`). |
| `Log` | `Level` one of the four (F4; a hand-built `slog.Level(3)` is rejected); `Format` one of two (F4). |
| `Data` | `Dir` non-empty after trimming and no NUL (F21). |
| `Modules` | each item non-empty after trimming, no duplicates, ≤ 64 items (F5). |

Reasons never echo string input, following `lib-core`'s rule: "must be a postgres:// or
postgresql:// URL with a host", "must be at least 32 bytes". Numbers and durations are
echoed ("must be between 1s and 10m, got 0s").

### `modules.disabled`: how enablement is derived (for `app.md`)

`config` delivers `Modules.Disabled` as given. `app`, which may import both `config` and
`core/module`:

1. Takes `names` = the `Name` of every manifest in `module.Default().Manifests()`.
2. For each entry in `Disabled` not in `names`: records
   `validate.FieldError{Field: "BMS_MODULES_DISABLED", Reason: "unknown module <name>; compiled-in modules are: <names>"}`
   (module names are not values an operator typed in secret, so they are echoed). Any such
   entry fails start-up with `errs.Invalid`, all of them listed, before `Resolve`.
3. Sets `module.Env.Enabled` = `names` minus `Disabled`, in registry order.

Resolve's own check that every enabled name is registered (module-contract F15) then holds
by construction. `bms check` runs the same derivation and reports the same error.

### Concurrency and lifecycle

`Load` has no shared state and may be called from any goroutine; in practice `cmd/bms`
calls it once. `Config` is a value: copying it copies `secret.Secret` pointers to immutable
strings and shares the `TrustedProxies` and `Disabled` slices, which nobody mutates after
`Load` (`app` treats them as read-only; a test reads them concurrently under `-race`). There
is nothing to start or close, no clock, no logger, no goroutine.

### Imports

Standard library (`context`, `encoding/json`, `errors`, `fmt`, `io`, `io/fs`, `log/slog`,
`net`, `net/netip`, `os`, `path/filepath`, `regexp`, `runtime`, `strconv`, `strings`,
`time`), `internal/lib/errs`, `internal/lib/validate`, `internal/lib/secret`. Not
`crypto/rand`: generation is `app`'s. Nothing else, enforced by a new depguard rule `config` (Proposed
change 1). `cmd/bms` and `internal/app` are the only packages allowed to import
`internal/config`; `core`, `modules` and `api` are denied it.

A missing secrets file is not a failure of `Load` (decision 3): `TestLoad_SecretsFileAbsent_LeavesSessionKeyUnset`
pins that `Load` succeeds and `Session.Key.IsSet()` is false.

Members that cannot fail, and why: `Keys` (returns a copy of a package-level table that a
test proves is complete and well-formed); `Default` (applies the same table's defaults,
which `TestDefault_WithRequiredSet_Validates` proves valid). Each has a success-path test.

## Lock-in check

No external technology. The environment, `*_FILE` secrets and `os.Environ` are POSIX and
Windows alike; `netip`, `slog` and `time.ParseDuration` are standard library. Nothing in the
catalogue names a vendor: `db.url` is any PostgreSQL (D8), the observability variables are
OpenTelemetry's (D20), and the front end behind `http.trusted_proxies` can be any proxy or
tunnel.

## Test plan

Unit tests only, no infrastructure, `go test -race`, table-driven, black-box package
`config_test`. Files for `*_FILE` cases are written to `t.TempDir()`. Every credential in a
test is an invented marker that cannot occur by accident (`ZQ9MARKER7` inside
`postgres://bms:ZQ9MARKER7@db.example:5432/bms`; a 48-byte session key of repeated marker
text); every leak check asserts `!strings.Contains(out, marker)`. No real host names,
passwords or people.

## Open questions

None. The three questions in the first draft were answered by the owner on 2026-10-16:

1. **Session key: set by the operator, or generated at installation?** Answered: generated
   during the initial installation and stored in a configuration file (as GitLab does),
   with a notice at installation that it must be backed up. Recorded in decision 7 (the
   secrets file, written once by `bms migrate` under `data.dir`, mode 0600, read by
   `config` as a third source; the notice text; future generated secrets in the same
   file), the `Secrets` section and `secrets.file` key, failure modes F22b–F27, and
   Proposed changes 3, 6 and 9.
2. **Must the binary terminate TLS itself?** Answered: offloading TLS is acceptable as long
   as it does not affect security. Recorded in decision 16 (the conditions that make it
   safe; what this spec enforces: loopback default, the bind rule F28,
   `http.allow_plaintext`; what `api` and the deploy docs enforce) and Proposed changes 5
   and 11. TLS in the binary is not planned; if a regional ever needs it, `http.tls.*`
   keys are a later addition.
3. **A `text` log format alongside D20's JSON?** Answered: yes, JSON by default with text
   for developers. Recorded in decision 15 and Proposed change 12.
